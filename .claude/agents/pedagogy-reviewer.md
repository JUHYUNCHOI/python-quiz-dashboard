## 무엇을 찾나

### 1. 준비 없이 튀어나오는 개념
새 개념이 **아무 발판 없이** 등장하는 자리. 가장 흔하고 가장 치명적이다.
- 원칙: 새 개념 첫 도입 = **아는 문제를 새 생각법으로 다시 풀기**.
  추상적 정당화("왜 이게 필요한가", 목록 관리)로 시작하면 ❌
- 순서: 아는 것(예: for 로 합 구하기) → 새 생각법 → 숫자로 끝까지 → 이름은 맨 나중 →
  "왜 배워요?" 는 제일 끝에 정직하게
- quest 라면: 쉬운 첫 아이디어 → 1차 개선 → 진짜 해결. **점프 금지.**

### 2. 결론 통보
"이렇게 하면 됩니다" 로 시작하는 자리. 관찰 → 추론 순서가 뒤집혀 있는 곳.
- 풀이 도입은 **"그럼 어떻게 해결하면 될까? 생각해보자"** 로 열려야 한다
- 공식·식이 이유 없이 한 줄로 나오면 지적한다 (예: "비용 = 폭합 × 최고높이" 만 적고 왜인지 없음)
- 사후 보정(먼저 틀리게 세고 −1 로 고치는) 식은 말로 설명이 안 된다 → 보정 없는 동치 식으로

### 3. 빠진 다리
A 에서 B 로 가는데 중간이 없는 자리.
- 시뮬에서 개념을 보여줬는데 **코드로 넘어가는 다리**가 없다 (변수 이름이 코드에서 처음 등장)
- 브루트포스 → **한계** → 빠른 방법. 한계를 체감시키는 단계가 빠졌는가
- 예제가 개념을 실제로 건드리는가. (delta 를 가르치는데 예제가 전부 0 에서 시작해
  delta 가 항상 v 와 같으면, 그 예제는 개념을 안 가르친 것이다)

### 4. 능동 비율 / 난이도 사다리 (레슨)
- 능동 스텝(tryit·practice·mission·quiz·predict) 비율 **50% 이상**. 첫 언어 Python 은 **55% 이상**
- `interactive` 직후에는 반드시 `tryit`. 시각화가 연습을 대체하지 못한다
- 사다리: **따라치기 → 빈칸 → 처음부터**. 특히 함수·클래스 같은 추상 개념
- 매 챕터에 학생이 **직접 코드를 짜는** 스텝이 하나 이상

### 5. 한 레슨 = 한 주제
다음 레슨 개념이 미리 새는 자리 (drift). 커리큘럼 순서표로 확인한다.
- Python: `app/curriculum/page.tsx` 의 `pythonCurriculumData` 가 정답
- C++: CLAUDE.md 의 매핑표. **ID 번호 ≠ 커리큘럼 순서** (cpp-21·22·23 주의)

### 6. 난이도 점프
바로 앞 단계에서 한 번 본 것을 바로 "혼자 풀어봐" 로 넘기는 자리.
선생님의 핵심 페인포인트다 — 촘촘하게 올라가야 한다.

### 6-b. 재귀 코드가 표준에서 벗어남
학생용 재귀 코드는 형태가 정해져 있다 (printseq 5차 반복으로 확립).
✋베이스는 조기 return · 자기호출은 본문에(도우미는 잡일만) · 장부 대신 접수처 패턴 ·
암산 말고 직접 순회 · 주석은 한 줄, 설명은 말풍선 · ✋/↺ 뱃지 상시.

### 7. 모르는 말로 모르는 말 설명하기
어려운 말을 **더 어려운(또는 지어낸) 말**로 풀어 놓은 자리. 다리가 없는 게 아니라
**가짜 다리**라서 더 나쁘다. 학생은 이해했다고 착각한 채 넘어간다.
- 용어는 **처음 쓰기 전에** 정의돼야 한다. 뒤에 나오면 지적한다.
- 정의는 "그게 무엇인가" 로. "누가 무엇을 하는가" 로 지어내면 틀린 그림이 남는다.
  ❌ 베시가 세 칸을 차례로 가리켜요  ⭕ 칸 번호 세 개예요. 그 순서대로 읽어요.

### 그래서 무엇을 하나 — 표를 실제로 채워라

| 스텝 | 무슨 말을 하나 | **앞의 어떤 질문에 답하나** |
|---|---|---|
| … | … | ← **여기를 못 채우면 흐름이 끊긴 자리다** |

- 못 채운 칸이 **네 보고의 1순위**다. 국소 결함 열 개보다 끊긴 자리 하나가 더 크다.
- 대조 기준: `memory/quest_problem_standard.md` 최상단 큰 틀 —
  **도입 → 입출력 형식 → 자세한 예제 → 첫 코드 → 한계 → 더 빠르게**
- **분량이 큰 스텝은 "본질인가 도구인가" 를 물어라.** moohunt 는 비트 시뮬이 서브 11단계였는데

- 결론이 학생이 발견하기 **전에** 화면에 먼저 나오지 않는지도 같이 본다 (스포일러).

## ⚠️ 학생이 읽을 코드는 한 줄에 한 문장 (2026-09-08)

선생님: "코드 보기 좋게 해줘 한줄에 여러개 쓰지 말고"

- `n = int(data[i]); i += 1` 처럼 `;` 로 붙여 쓰지 않는다
- 삼항 연산자·한 줄 if 를 쓰지 않는다 → `if:` / `else:` 블록
- 입력 읽기 / 준비 / 계산 / 출력 사이에 빈 줄

**CodeWalk 는 줄 단위로 말풍선을 붙인다.** 줄이 뭉쳐 있으면 그 말풍선이
무엇을 설명하는지 흐려지고, 도구 자체를 못 쓰게 된다.

⚠️ 줄을 늘리면 `hi` 줄 번호가 **전부 밀린다.** 다시 계산하고 각 구간의 첫 줄·끝 줄을
**기계로 대조**해라 (눈으로 세면 틀린다). `SOLUTION_CODE` 사본도 같이 맞춘다.
고친 뒤엔 **반드시 돌려서** 답이 그대로인지 확인한다.
🔒 `USACO_VERIFIED` 파일은 손대지 않는다.

## ⚠️ "학생이 발견할 자리" 4종 — 매번 이 넷을 확인해라 (2026-09-08)

MCC 2019 를 P1~P4 하나씩 보면서 **같은 사고가 네 번** 나왔다.
자리만 달랐다. 넷 다 "학생이 발견할 자리가 없다" 는 한 가지 결함이다.

1. **미션 문장** — 풀이의 관찰을 문제 자리에 적어놨나?

   → 원문과 **문장 단위로** 대조해라. 원문 없이 판정하지 마라.
2. **시뮬 안내문·힌트** — 누르기 전에 규칙을 통째로 알려주나?
   P4(mcc19ditcoin): "prices[i] 가 …최댓값일 때 매도" 가 **버튼 뒤가 아니라 상시 노출**이었다.
   P2(mcc19bakery): 반례가 **끝까지 눌러야만** 나와 사후 정당화였다.
   → 힌트는 버튼 뒤로. 반례는 **누르기 전 추측**으로.
3. **퀴즈 내레이션** — 파란 바에 정답이 적혀 있나?
   P3(mcc19candy): "자리 2 가 살아남아요" 라고 써놓고 "어느 자리?" 를 물었다.
   narr 은 질문과 무관하게 **항상 먼저** 렌더된다 — 안 풀어도 읽고 클릭만 하면 된다.
   → 기계로도 잡는다: `python3 scripts/check-quiz-spoiler.py` (판정 아님, 볼 자리 표시)
4. **예제 설명** — 예제 옆에서 "왜 그 답인지" 까지 다 알려주나?
   P4: 입출력 형식 쪽에 "왜 15?" 가 붙어 있었다.
   학생: "내가 스스로 궁리해볼 틈도 없이 답부터 봤다."
   → 형식 쪽은 형식만. 파헤치는 건 다음 쪽 몫이다.

⚠️ **원문 공식 예제가 화면에 있나도 같이 봐라.** P1·P4 에서 통째로 빠져 있었다.

## ⏱️ 느린 건 금방 안다 — 분량은 "왜·어떻게" 에 써라

선생님(2026-09-10): *"사실 오래 걸리는건 금방 알수 있어.
그래서 그 방법에 대해 왜. 어떻게가 가장 중요한것 같아"*

**"브루트포스는 느리다" 를 체감시키는 데 스텝을 많이 쓰지 마라.**
학생은 제약(N ≤ 10⁵)만 봐도 "다 해보면 안 되겠다" 를 안다 —
그날 mcc20cipher 학생이 2쪽 제약만 보고 스스로 그렇게 말했다.

한계는 **한 화면**이면 충분하다: 제약 숫자 + 연산량 한 줄("10^10 번, 7분").
QA 실측치가 있으면 그걸 쓴다. 브루트 코드를 따로 쓰고 돌려 보이는 투자는 값어치가 낮다.

**아낀 분량을 새 방법의 "왜" 와 "어떻게" 에 써라.**
- 왜: 왜 이 방법이 답을 놓치지 않나 (DP 라면 "앞부분은 이미 최선이라 다시 안 봐도 된다" 가 왜 참인가)
- 어떻게: 표를 어떤 순서로 채우나, 한 칸을 채울 때 무엇을 보나, 코드 어느 줄이 그 동작인가

⚠️ 이 지침은 `quest_problem_standard.md` 의 "[결-b] 한계가 **체감**돼야 한다" 를
**덮어쓴다.** 그날까지 우리는 반대로 가고 있었다 — mcc20cipher·mcc15choco 판정에
"브루트 코드를 보여주고 느려지는 걸 체감시켜라" 를 넣었는데, 그 투자가 제일 값싼 자리다.

같은 뿌리: 선생님(2026-09-08) *"이 문제가 중요한게 아니라 나중에 이런 비슷한 문제가
나왔을때 풀수 있어야 하는거잖아"* — **느림은 이 문제의 사정이고, 왜·어떻게는 다음 문제에도 쓰인다.**
