## 무엇을 찾나

### 1. 같은 말이 두세 번 (제일 흔함)
한 화면에서 **위 내레이션 · 말풍선 · 아래 박스**가 같은 내용을 반복하는 자리.
선생님이 반복해서 지적한 것: "한번에 설명이 너무 많아", "여기 정보가 너무 많아".
→ 말풍선 하나만 남기고 나머지는 지운다.

### 2. 파란 내레이션 바가 김
`narr` 필드는 **한 문장, 55자 이하**. 자세한 건 아래 카드·시뮬이 한다.
```bash
grep -n 'narr: t(E' <파일>     # 한국어 쪽 길이 확인
```

### 3. 겹침
절대배치(`position: absolute`) 한 요소가 다른 것 위에 올라타는 자리.
특히 **격자 위에 띄운 이름표·말풍선·행열 번호**. 값이 바뀌면(모서리 케이스) 겹치기 시작한다.
→ 격자 위에 띄우지 말고 **격자 밖 범례**로 빼는 게 안전하다.

### 4. 한 화면에 안 들어옴
세로로 계속 쌓아서 스크롤해야 보이는 자리.
→ 옆으로 배치(격자 ︱ 표), 또는 **시뮬 스텝을 늘려서 한 판에 한 가지만**.
선생님: "시뮬스텝을 올려서라도 더 짧게 써줘."

### 5. 글자 색이 전부 같음
설명·식·결론·숫자가 한 색이면 눈이 길을 잃는다.
선생님: "중요한건 글자 색을 제발 다르게 하자."
→ 역할별로: 회색=말로 하는 설명 · 남색=식 · 주황=이번에 새로 나온 결론 · 초록=숫자 대입

### 6. 한글 줄바꿈 4종 세트
한글 텍스트에 **넷 다** 있어야 한다:
- `wordBreak: "keep-all"` (단어 중간에서 안 갈리게)
- `textWrap: "balance"` (마지막 줄만 짧게 남는 것 방지)
- 한 줄 60자 이하
- **절 단위로 `<br />` 직접 삽입** (자동 줄바꿈에 맡기지 않기)

```bash
grep -n 'wordBreak' <파일> | grep -v textWrap    # balance 빠진 곳
```

### 7. 말투
- **해요체** 통일. 반말("~해봐", "~하지") 섞이면 지적
- 숫자 뒤 조사 (`6 로` / `6 으로`) — 값이 바뀌면 틀리니, 조사를 피하는 문장으로
- 기호로 쓴 설명 ("사진 = 3×3 조각") 은 말로 ("사진은 아무 데서나 잘라낸 3×3 조각이에요")

### 8. 시뮬 스타일 통일
`@/components/quest` 의 `SimNav`(◀▶ 단계) + 말풍선. **자동재생 금지.**
새로 발명하지 말고 형제 quest(같은 시즌)를 열어 같은 모양으로.

### 9. 답 노출
문제 화면에 정답이 미리 보이는 자리 — 주석·`initialCode`·보기 안 해설·시뮬 초기값.

## 절대 하면 안 되는 것

- **파일을 고치지 마라.** 검토하고 보고만 한다.
- "예쁘게 하자" 같은 취향 얘기 금지. **읽히느냐**만 본다.
- 내용이 맞는지, 코드가 도는지는 보지 마라. 다른 에이전트 일이다.

## 보고 형식

심각한 것부터. 각 항목에 **① 어디(파일:줄, 어느 스텝) ② 무슨 문제 ③ 아이 눈에 어떻게 보이나 ④ 어떻게 고치나**.

```
● quest-problems/xxx/sims.jsx:312 — clamp 단계  [겹침]
  문제  : 액자 이름표를 격자 위 -11px 에 절대배치
  보이는 것 : 소가 1행에 있으면 이름표가 열 번호·말풍선 꼬리와 겹쳐 글자가 뭉갬
  고치기 : 이름표를 격자 밖 범례 한 줄로 빼기 (값이 바뀌어도 안 겹침)
```

마지막에 **"가장 먼저 고칠 것 3개"** 를 순서대로 뽑아라.
