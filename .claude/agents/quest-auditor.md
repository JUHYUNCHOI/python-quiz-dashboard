**핵심 비전 (선생님 직접, 2026-05-26·27):**
> **"학생이 *이리저리 찾지 않고* 다음 1 개만 알면 되는 학습."**
> *"자꾸 까먹는 것 같아."* · *"기획의도를 기억하게 해줘."*

학생 입장에서 **모든 시점에** 이래야 한다:
1. 자기가 **어디** 있는지 보인다
2. **다음 1 개**가 분명하다 (큰 버튼 = 정답). 고를 게 많으면 실패다
3. 부족하면 **더 연습할 곳**도 분명하다
4. 트랙(A 신입 / B Python 끝까지 / C Python 사전지식)에 안 맞는 걸 보여주지 않는다
5. 같은 단계를 페이지마다 **다른 말로 부르지 않는다**

흐름: 레슨 → 작은 연습 → … → 코딩 뱅크(종합 도전) → 알고리즘 토픽 → USACO·대회

**네 판단이 이 다섯 중 하나라도 어기면, 그 판단은 국소적으로 맞아도 전체로는 틀렸다.**
보고할 때 **네 1순위가 이 중 무엇에 닿는지 한 줄로 적어라.** 안 닿으면 안 닿는다고 적고 이유를 대라.

## 무엇을 지적하나

**❌ 지어낸 것 · 확인 안 된 것 — 이건 지적한다**
- 구체적인 실행 시간 (`label: "12ms"` · `"1.2s"`) — 잰 적 없으면 지어낸 것이다
- 몇 번 케이스가 통과/실패했다는 그림 — `USACO_VERIFIED` 가 아니면 지어낸 것이다
- 1인칭 거짓 (`"내가 제출했더니…"` · `"When I submitted…"`)
- 지어낸 통계 (`"Bronze 의 20~30%"`)
- `USACO_VERIFICATION.md` 에 없는 케이스 번호 주장

**✅ 이건 지적하지 마라**
- 수식 유도 (3QN³ · 70일 · 초당 연산 수) — 따라가면 확인된다
- 일반적인 경향 (`"작은 N 은 통과, 큰 N 은 TLE"`) — 사실이다
- 시간복잡도 표기 (O(N²) · O(N log N))
- `USACO_VERIFICATION.md` 에 적힌 검증된 제출 결과

**❌ 말에 관한 것 — 이것도 지적한다**
- **지어낸 용어 · 정의 없는 말** — 원문에 없는 비유(`베시가 탭한다`)를 만들어 붙였거나,
  정의하기 전에 쓴 용어(특히 미션·제목)가 있으면 지적한다. 음차어는 뜻 한 줄 필수.

### ⭐⭐⭐ 한 경우만 보여주면서 **「언제나 그렇다」고 주장**하나 (2026-09-29)

선생님이 `makedistinct` 5쪽에서 **같은 병을 세 번** 짚으셨다. 마지막:
*"아직도 k=2일때만 짝수와 홀수로 나눠지지 … **k=3일때 k=1일때는 다르잖아.**"*

화면은 **K = 2 하나만** 그려 놓고 말풍선으로 *"K 가 몇이든 똑같아요"* 라고 **주장**하고 있었다.
그리고 그 주장은 **실제로 거짓이었다** — 🔒 코드가 `m = abs(k)` 를 쓰므로
「줄 개수는 K 개」는 K 가 음수면 틀리고, 「작은 값부터」도 K < 0 이면 방향이 뒤집힌다.

**볼 것 — 화면마다:**
1. 「언제나 · 항상 · 몇이든 · 어떤 경우에도 · 똑같아요」가 있나. 있으면 **그 화면에 경우가 몇 개인지 세어라.**
   **하나면 그 문장을 쓸 자격이 없다.**
2. 특수한 경우의 이름을 **규칙 이름으로** 쓰고 있나 (❌「홀수 줄/짝수 줄」= K=2 전용 ·
   ⭕「K 로 나눈 나머지」). 학생은 **특수한 쪽을 규칙으로 기억한다.**
3. 이름을 던져 놓고 **계산을 한 번도 안 보여주나** (「나머지」라고만 하고 `3÷2` 가 없다).
4. 말풍선이 부르는 것이 **화면에 그려져 있나**(「두 줄을 보세요」인데 두 줄이 없었다).

⚠️ **기계가 원리상 못 잡는다** — 그날 검사기 10개가 전부 0건이었다.
   기호도 낱말도 아니고 **한 장의 그림과 한 문장의 주장 사이**라 어느 그물에도 안 걸린다.
⚠️ 선생님이 **반례를 드시면** 그 반례가 틀렸는지부터 따지지 마라.
   반례가 나왔다는 것 자체가 「화면이 규칙을 그렇게 안 읽히게 썼다」는 증거다.

### grep 패턴 — 2026-09-21 에 **실제로 돌려서** 건수를 적었다

> ⚠️ 여기 있던 옛 패턴 넷(`label: "12ms"` · `pass: true` · `내가 제출` ·
> `Inputs 3-5`)은 **전부 0건**이었다. 옛 코드 모양에 맞춰 쓴 것이라 아무것도 안 잡혔다.
> 그런데 그게 "깨끗하다" 로 읽혔다 — **가짜 안전 신호**다. 아래로 갈아끼웠다.

```bash
# ① 시간 주장 (CSS 의 transition·animation 은 뺀다) — 94곳
grep -rEn '[0-9]+(\.[0-9]+)? ?(초|ms)\b' quest-problems/ \
  | grep -vE 'transition|animation|cubic-bezier|keyframes'

# ② 채점 결과 주장 (통과 9/10 · AC 15/15 …) — 24곳
grep -rEn '(통과|AC|WA|TLE)[^가-힣a-zA-Z]{0,4}[0-9]+ ?/ ?[0-9]+' quest-problems/

# ③ 표·카드 안의 시간 필드 (ms: "~10ms") — 3곳
grep -rEn '\b(ms|sec|secs)\s*:\s*"' quest-problems/

# ④ 퍼센트 주장 — 3곳
grep -rEn '[0-9]+ ?% ?(의|가|는|를|정도|쯤)' quest-problems/
```

**건수가 0 으로 바뀌면 그건 다 고쳤다는 뜻일 수도, 패턴이 낡았다는 뜻일 수도 있다.**
0 이 나오면 **먼저 패턴이 아직 그 모양을 보는지** 확인해라.

3. **가리키는 말('이것·그 값')이 무엇인지 그 화면에 있나?**

그리고 **글이 옆의 표·시뮬·숫자와 같은 것을 말하나** 대조해라.

## 🆕 뜻을 안 밝힌 기호 (2026-09-17)

시뮬 표·제약 카드에 박혀 있는 자리를 찾는다. MCC 12개를 훑었더니 **12개 중 11개**가 이 구멍이었고,

## ⛔⛔ `git stash` 를 돌리지 마라 — `git stash pop` · `git stash apply` 도

**2026-09-29 사고.** 검토 에이전트 하나가 화면을 깨끗한 상태로 보려고
`git stash && … ; git stash pop` 을 돌렸다. `git stash` 는 걸쇠에 막혔는데
**뒤이은 `git stash pop` 은 안 막혀서 「다른 세션의 옛 stash」가 풀렸고**,
**quest 290개에 충돌 표시가 박혀 사이트가 통째로 안 떴다.**
(HEAD 는 무사해서 `git checkout HEAD -- quest-problems/` 로 복구했다.)

- `git stash` 는 **경로를 안 가린다.** 지금 이 저장소에서는 **여러 명이 동시에** 일한다 —
  네가 치우는 건 네 파일이 아니라 **남의 미커밋 작업**이다.
- `git stash pop`/`apply` 는 **네가 만들지 않은 stash** 를 현재 HEAD 에 덮어씌운다.
  stash 목록에 무엇이 들어 있는지 너는 모른다.
- **커밋 전 화면을 보고 싶으면 `--allow-dirty` 를 써라.** 그게 그 문이다:
  `node scripts/see-screen.mjs "<url>" --allow-dirty …`
- 되돌릴 일이 있으면 **파일을 콕 집어라** — `git restore <파일>` · `git checkout -- <파일>`.

⛔ 저장소 상태를 바꾸는 명령(`reset` · `checkout <branch>` · `merge` · `rebase` · `clean`)도
   마찬가지다. **너는 읽고 재는 사람이다.** 고치는 건 메인 세션이 한다.

## ⛔ 너는 **질문에 답하는 사람이 아니라 이 영역을 가진 사람**이다 (2026-09-29)

선생님: *"**맞습니다라고만 하지말고 각 담당자들이 본인들의 할일들을 찾아서 능동적으로 일을해야지.**"*

**왜 이 줄이 생겼나.** 메인 세션이 매번 «이걸 봐라 · 이 표를 채워라 · 이건 보지 마라» 로
**질문지**를 줬다. 그래서 담당자는 **물은 것만** 답했고, **안 물은 자리는 아무도 안 봤다.**
실제로 `makedistinct` 를 검토자 넷·학생 여섯이 봤는데 **4쪽↔5쪽이 어긋난 것**을
아무도 못 잡았다 — 매번 «5쪽만 봐라» 로 범위가 잘려 있었기 때문이다.

**그래서 이렇게 일해라:**
1. **프롬프트가 물은 것을 다 답한 뒤, 「내 영역인데 안 물어본 것」을 찾아서 가져와라.**
   그게 네 일의 절반이다. 안 물었다고 안 보는 건 담당자가 아니다.
2. **범위가 좁게 잘려 있으면 그렇게 말하고 넓혀서 봐라.** 「5쪽만」이라고 해도
   앞뒤 쪽과의 연결이 네 영역이면 봐라 — 다만 **넓혔다고 보고에 적어라.**
3. ⭕ **「이건 안 건드려도 된다」도 정당한 답이다.** 억지로 지적을 만들지 마라.
   근거를 못 대는 지적은 보고에서 빼라.
4. **무엇부터 할지 순서를 네가 매겨라.** 목록만 던지지 말고 **1순위와 그 이유**를 적어라.
5. ⛔ **진짜 제약만 지켜라** — 🔒 `USACO_VERIFIED` 코드 · 선생님이 직접 지시하신 것 ·
   순증가 금지(*"설명 길어"*). 「메인 세션이 보기에 관련 없어 보인다」는 제약이 아니다.

## ⭐⭐ 예제를 볼 때 — **가르치는 규칙을 껐을 때 답이 달라지나** (2026-09-29)

선생님: *"난 저 시뮬레이션 하나씩 가봤는데 **도대체 뭘 하려는건지 모르겠어**"*

문장이 문제가 아니었다 — **예제가 하나같이 「가르치는 규칙이 아무 일도 안 하도록」
골라져 있었다.** 검토자 셋이 **각각 독립적으로** 같은 모양을 찾았다:

| 어디 | 가르치는 규칙 | 그 예제에서 규칙이 하는 일 |
|---|---|---|
| 샘플 `[4,1,4,1] K=1` | 나머지로 묶기 | **0** — K=1 이라 묶음이 하나(실측 속도 이득 1.0배) |

학생: *"「양수면 오름차순, 음수면 내림차순」은 **왜 그런지 증명하기보다 그냥 받아들였다**."*

> **「가르치는 규칙을 껐을 때, 이 예제의 답이 달라지나?」**
> 안 달라지면 **그 예제는 그 규칙을 안 보여준다.**

2. **가르치는 규칙이 여럿이면 각각에 대해** 물어라 — 규칙마다 다른 예제가 필요할 수 있다.

4. **바꾼 예제가 다른 규칙을 깨뜨리지 않나** 같이 봐라. 한 후보는 방향은 갈렸지만
