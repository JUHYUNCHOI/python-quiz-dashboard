# 피드백을 기억으로 남기기

**왜 이게 있나:** 2026-09-04, moohunt 에서 "용어를 지어내지 마라" 는 지적을 받고 파일만
고치고 끝낼 뻔했다. 선생님이 *"지금 내가 말하는 피드백을 누가 기억해야 하는거지?"* 라고
물어보셔서 겨우 남았다. **기록이 내 판단에 달려 있으면 대부분 사라진다.** 이 절차는
그 판단을 없애려고 있다.

아래 5 단계를 **순서대로, 하나도 건너뛰지 말고** 한다.

## 1. 이미 있는지 먼저 본다

```bash
ls ~/.claude/projects/-Users-juhyunchoi-Coding-python-quiz-dashboard/memory/
grep -rn "<핵심어>" ~/.claude/projects/-Users-juhyunchoi-Coding-python-quiz-dashboard/memory/
```

비슷한 게 있으면 **새로 만들지 말고 그 파일을 고친다.** 중복 파일이 제일 나쁘다.

⚠️ **범위를 확인해라.** 비슷해 보여도 적용 대상이 다르면 별개 파일이다.
실제 사례: `feedback_korean_natural_writing.md` 에 "지어낸 말 금지" 가 있었지만
그 파일이 스스로 *"이건 페이지가 아니라 내 답변에 대한 규칙"* 이라고 범위를 좁혀놔서
**학생용 페이지 글에는 아무 효력이 없었다.** 그래서 별도 파일을 만들었다.

## 2. 메모리 파일을 쓴다

`memory/feedback_<주제>.md` (project 면 `project_`, reference 면 `reference_`)

```markdown
---
name: <kebab-case-slug>
description: <한 줄. 나중에 이 줄만 보고 관련 있는지 판단한다>
metadata:
  node_type: memory
  type: feedback | user | project | reference
담당: <agent 이름들, 쉼표로. 없으면 "나(메인 세션)">
---

선생님(YYYY-MM-DD, 어디서): "<원문 그대로 인용>"

**Why:** 왜 이게 문제였나. **내가 무엇을 잘못했는지 구체적으로.**
추상적으로 쓰면 다음에 못 알아본다.

**How to apply:** 다음에 같은 자리에서 실제로 할 행동. 번호를 매겨서.
❌ / ⭕ 예시를 실제 문장으로 붙인다.

같이 볼 것: [[다른-메모리-이름]]
```

**인용은 반드시 원문 그대로.** 내 말로 요약하면 뉘앙스가 날아간다.

## 3. MEMORY.md 에 색인 한 줄

`MEMORY.md` 는 **매 세션 자동으로 읽히는 유일한 목록**이다. 여기 없으면 파일은 없는 것과 같다.
알맞은 절(`## Feedback` / `## Project` / `## Standard`)에 한 줄:

```
- [⭐ <짧은 제목>](./feedback_xxx.md) — <핵심 한 줄>. 선생님(날짜) "<짧은 인용>". **<언제 읽어야 하는지>.**
```

마지막 굵은 부분(**언제 읽어야 하는지**)을 빠뜨리지 마라. 그게 없으면 안 읽힌다.

## 4. 담당 에이전트에 배포한다  ← **여기를 제일 많이 빠뜨린다**

메모리에 적는 것만으로는 **서브에이전트가 모른다.** 에이전트는 자기 `.md` 만 읽는다.

먼저 담당을 정한다:

| 피드백이 무엇에 대한 것인가 | 담당 |
|---|---|
| 화면·전달·글자·겹침·용어 | `ux-reviewer` |
| 순서·스캐폴딩·빠진 다리 | `pedagogy-reviewer` |
| quest 정직성·과장 | `quest-auditor` |
| 레슨 콘텐츠 품질 | `lesson-content-reviewer` |
| 코드가 실제로 도는지 | `python-qa` / `cpp-qa` |
| 화면 구현·상태·빌드 | `frontend-engineer` |
| DB·배포·서버 | `backend-engineer` |
| 여러 파일에 패턴 적용 | `ui-pattern-applier` |
| 알고리즘 챕터(`app/algo/*`) 콘텐츠 | `algo-chapter-builder` |
| 우선순위·전체 현황 | `project-lead` |
| 내 말투·내 답변 | 나 (메모리에만) |

그다음 `.claude/agents/<담당>.md` 를 **Edit** 해서 항목을 넣는다.
검토자면 "무엇을 찾나" 절에, 작성자면 규칙 절에. 끝에 근거를 남긴다:
`근거: memory/feedback_xxx.md`

⚠️ **학생 에이전트(`student-*`)는 예외.** 정의 1번이 "품질 기준 문서를 읽지 마라" 다.
규칙을 알려주면 그 규칙에 맞춰 찾아버려서 학생이 아니게 된다.
넣으려면 **규칙이 아니라 행동**으로만: "뜻 모르는 말이 나오면 때려맞히지 말고 적어라".

## 5. 커밋한다

```bash
git add .claude/agents/ && git commit -m "docs(agents) <피드백 한 줄> 을 담당 에이전트에 배포"
```

메모리 폴더(`~/.claude/…`)는 저장소 밖이라 커밋 대상이 아니다. 에이전트 파일만 커밋한다.

## 끝나고 보고할 것

- 어느 파일에 남겼는지 (새로 만들었나, 기존 것을 고쳤나)
- **누가 담당인지** — 이게 선생님이 실제로 물으신 것이다
- **아직 검증 안 된 것** — 배포했다고 걸러지는 건 아니다. 돌려보기 전엔 그렇게 말해라.
