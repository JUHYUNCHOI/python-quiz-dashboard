# 결정은 한 사람이 하지 않는다

**왜 이게 있나:** 2026-09-04, 배포를 project-lead 혼자 판정하고 내가 근거 하나만 확인하고 밀었다.
선생님: *"누군가 하나가 판단하는게 아니라 모든 agent가 의논을해서 결정하거나
project lead랑 상의해서 다시 생각해줘."*

같은 날 증거가 이미 있었다.
- **여러 명에게 물었을 때** — moohunt 를 ux·pedagogy·student 셋이 각각 보고,
  **겹치는 지적만** 진짜 문제였다. 안 겹친 건 대부분 한 명의 오독이었다.
- **의견을 부딪혔을 때** — 메모리 구조를 두고 내가 project-lead 에 반대했고,
  근거 대조 끝에 그 사람이 자기 안을 접었다. 더 나은 답이 나왔다.
- **혼자 판단했을 때** — 별표 393곳을 내가 혼자 지우다 동결 quest 의 정답 코드를 깨뜨렸다.

## 언제 쓰나

- **배포 · main 머지**
- **콘텐츠 삭제** (퀴즈·챕터·시뮬·quest)
- **구조 변경** (챕터 재배치, 컴포넌트 이관, 표준 바꾸기)
- **여러 파일에 한꺼번에 적용하는 일괄 작업**
- 담당이 갈리거나, 선생님이 "어떻게 할까" 라고 물으실 때

작은 텍스트 수정이나 명백한 버그 하나는 이 절차가 필요 없다. 그냥 고쳐라.

## 3라운드

### 1라운드 — 각각, 서로 안 보게

관련 담당자에게 **동시에, 서로의 답을 모르는 채로** 묻는다.

⚠️ **서로 보게 하면 의논이 아니라 추인이 된다.** 먼저 본 의견에 끌려간다.
독립적으로 물어야 **겹치는 지적 = 진짜 문제**라는 신호가 생긴다.

프롬프트에 매번 넣을 것:
- **"근거를 못 대는 지적은 빼라"**
- **"확인 못 한 건 확인 못 했다고 정직하게"**
- 겹칠 만한 담당끼리는 범위를 갈라줘라 (예: "용어는 ux 담당, 너는 흐름만")

### 2라운드 — 서로의 답을 보여주고 반박시킨다

1라운드 결과가 갈렸으면 **거기가 볼 만한 자리다.** 갈린 지점만 추려서 다시 묻는다.

- **"네 반론이 틀렸으면 틀렸다고 말해라. 나는 내 안을 방어하려는 게 아니라 맞는 답을 원한다"**
- 사실로 판정 가능한 것은 **코드로 확인시켜라.** 의견 대 의견으로 끝내지 마라.

### 3라운드 — project-lead 가 종합한다

**"제가 정했습니다" 가 아니라 이렇게 낸다:**

> A 는 이렇게 봤고, B 는 저렇게 봤다. 갈린 이유는 이것이다.
> 나는 이런 근거로 A 를 택한다. 이건 아직 확인 못 했다.

**갈린 지점을 숨기지 마라.** 숨기면 선생님이 뒤집을 근거를 잃는다.

## 결정 종류별 참여자

| 결정 | 물어볼 사람 |
|---|---|
| 배포·머지 | project-lead + python-qa · cpp-qa(실행 검증) + 바뀐 영역 담당 |
| 학생 화면 구조 변경 | ux-reviewer + pedagogy-reviewer + student-*(해당 과목) |
| 콘텐츠 삭제 | 그 영역 담당 + quest-auditor(🔒 동결 목록 대조) |
| 레슨 내용 | lesson-content-reviewer + pedagogy-reviewer + student-*(해당 과목) |
| 일괄 작업 | 담당 + quest-auditor(동결 목록) — **반드시 대조 후 시작** |

## 끝나고

1. **결정과 갈린 지점을 `.claude/WORK.md` 에 남긴다.** 대화창에만 두면 사라진다.
2. 실행은 메인 세션이 한다. **에이전트가 배포·머지를 직접 실행하지 않는다.**
3. 실행 후 **결과를 직접 확인**해라 (라이브 화면·빌드·검사기). 보고를 믿지 마라.
